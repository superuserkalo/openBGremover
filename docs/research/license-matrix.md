# License matrix: encoders, tools, and models under AGPL-3.0

Resolves [#10](https://github.com/superuserkalo/openBGremover/issues/10)
(part of map #2). Researched 2026-10-16.

openBGremover is AGPL-3.0 ([LICENSE](../../LICENSE)) and runs as a hosted
commercial service. This matrix records, for each candidate dependency, the
source license, the model-weight license where applicable, compatibility with
an AGPL-3.0 project, hosted commercial use, and codec patent exposure.

It builds on the license notes already in
`media-capabilities-research-2026-10-15.md`,
`ocr-options-research-2026-10-15.md`,
`audio-options-research-2026-10-15.md`,
`upscaling-video-research-2026-10-15.md`, and
[background-removal-quality-research.md](../background-removal-quality-research.md).
Those notes agree with what is verified here. The one exception is Whisper,
where the Hugging Face card metadata differs from the repository statement
(see below).

This is engineering due diligence, not legal advice. Every claim links to the
upstream license file, model card, or licensing page that owns it. GitHub's
license detection was cross-checked against the actual files, because it
reports `NOASSERTION` for multi-license projects.

## Policy reading

- **AGPL-3.0 compatibility rule.** The project can combine its code with
  permissive code (MIT, BSD, ISC, IJG, zlib, Apache-2.0), LGPL-2.1+/LGPL-3.0,
  MPL-2.0, GPL-3.0 (AGPL-3.0 section 13 explicitly permits this), and
  GPL-2.0-*or-later* (upgraded to v3). GPL-2.0-*only* code, and any license
  that FSF or FFmpeg classifies as GPL-incompatible, cannot be combined.
- **Hosted use.** Because our own code is already AGPL, copyleft
  dependencies (GPL/AGPL) add no new obligation beyond what we already do.
  We publish complete corresponding source, including any modified dependency
  source, to network users. The constraint is on the *future*: copyleft
  dependencies bind any proprietary fork or closed hosted layer, whether ours
  or a self-hoster's.
- **Excluded by policy:** noncommercial, research-only, or proprietary terms.
  Dependencies that make a build "nonfree" or unredistributable are excluded
  too.
- **Patents are separate from copyright.** A BSD or GPL encoder does not
  license the codec's patents. Patent status is noted for each codec.

## Codec patent summary (hosted transcoding)

| Format | Status | Recommendation |
| --- | --- | --- |
| JPEG (baseline), PNG, GIF, QOI | Patents expired or none | Default-safe. |
| WebP, VP8/VP9 | Google royalty-free grant | Default-safe. |
| AV1 / AVIF | AOM Patent License 1.0, royalty-free, defensive termination | Default for modern image/video output; residual third-party pool risk. |
| JPEG XL | Google grant for its own claims | Safe to offer. |
| Opus | Royalty-free grants from holders | Default audio output. |
| H.264 / AVC | Via LA pool | Business decision; decoding input is lower exposure than offering paid encode. |
| HEVC / H.265 / HEIC | Multiple pools (Access Advance, Via LA, independents) | Highest risk; avoid encode by default, decide on decode-only input. |
| AAC | Via Licensing pool; FDK library itself excluded | Prefer Opus; native FFmpeg `aac` only after a patent decision. |

## Actions implied for implementation tickets

1. Build FFmpeg without `--enable-nonfree`. Record the `configure` line and
   publish it with the source offer. Enable `--enable-gpl --enable-version3`
   only if x264/x265 are adopted.
2. Default outputs: JPEG (MozJPEG/Jpegli), PNG (OxiPNG, pngquant optional),
   WebP, AVIF, JXL, Opus, AV1/VP9. Keep H.264/HEVC/HEIC/AAC *encoding* behind
   an explicit product and patent decision.
3. Build Ghostscript without `jpegxr/`. Keep Artifex's producer/metadata
   notice. Prefer pdfium for rasterization if a non-AGPL path is ever needed.
4. Keep a third-party notices file covering IJG, BSD, MIT, Apache NOTICE,
   CC-BY attribution (Parakeet), and pngquant original-author attribution.
   Record the source URL, revision, and SHA-256 of every model weight.
5. Ask the HAT authors for an explicit weight license before shipping HAT.
6. Copyleft dependencies (pngquant, libimagequant, RVM, Ghostscript, MuPDF,
   x264/x265) are compatible today. Each one prevents a future proprietary
   fork or closed hosted tier unless replaced or commercially licensed.

## What would change this

- Moving away from AGPL-3.0 for any part of the hosted product would
  reclassify every GPL/AGPL row as "needs commercial license".
- A new pool assertion against AV1 or VP9 would change the default-output
  recommendation.
- New model releases need their own card check. Licenses differ per
  checkpoint, as Whisper and Surya show.
